# MicroClaw v0.6.0 execution plan

Status: **Active**
Updated: **2026-09-04**

MicroClaw 0.6.0 turns the capabilities delivered incrementally in 0.5.x into
one versioned product contract across Server, Work, the SDK, and every shared
Rust crate. The release is intentionally focused: governed Skills, observable
delegation, one shared Agent Engine, and a coherent downstream SDK surface.

## Release contract

1. **One version:** Server, Work, Work Headless, Work application/runtime
   crates, Core, Engine, SDK, and the two web packages report `0.6.0`.
2. **Governed Skills:** Work and SDK use the shared Engine lifecycle for local,
   GitHub, and ClawHub installation; discovery, source/version display,
   enablement, compatibility failures, and recoverable removal remain visible.
3. **Controlled delegation:** the Main Agent owns the conversation and
   Workspace. Durable Subagents are observable and cancellable, while all file
   mutations pass through the existing single-writer policy boundary.
4. **One kernel:** Server and Work continue to enter execution through the SDK
   and shared Agent Engine. No provider or Agent Loop implementation moves into
   a UI or channel adapter.
5. **Usable SDK:** the public `minimal`, `standard`, and `full` tiers compile as
   downstream dependencies, with runnable examples for Skills, delegated tasks,
   custom executors, and configured agents.

## Acceptance gates

- Version-alignment CI rejects drift between Server, Work, SDK, internal Work
  crates, and web package metadata.
- Runtime-boundary and standalone SDK-consumer checks pass.
- Work application, Work runtime, Engine, SDK, and complete workspace tests
  pass from the release commit.
- Clippy passes for the complete workspace and all features.
- Web UI and documentation builds pass; generated references have no drift.
- The three public crates publish in dependency order and pass the registry
  consumer smoke test.
- Release assets and portable Work previews are produced from `v0.6.0`.

## Release sequence

1. Align package metadata and dependency requirements at `0.6.0`.
2. Record the 0.6 product contract and upgrade notes.
3. Run focused checks, then the complete local release matrix.
4. Commit and push the verified release commit.
5. Publish `microclaw-core`, `microclaw-engine`, and `microclaw-sdk` from
   `sdk-v0.6.0`.
6. Tag `v0.6.0`, build Server and Work assets, and verify remote CI.
7. Mark this plan Delivered only after registry and release evidence exists.
