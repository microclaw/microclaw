# MicroClaw v0.11.0 execution plan

Status: **Delivered**
Updated: **2026-10-25**

MicroClaw 0.11.0 is a web UI dependency release that follows the 0.10.1
hotfix. The runtime and SDK contract are unchanged; the embedded web bundle
moves off the frozen `@assistant-ui` 0.14 line, and the web UI gains its
first automated test.

## Scope

- `@assistant-ui/react` 0.15 (0.15.31) with `@assistant-ui/react-markdown`
  0.14.24. `@assistant-ui/react-ui` has no 0.15-compatible release, so the
  chat thread is rebuilt on the `@assistant-ui/react` primitives with a
  vendored base stylesheet, keeping the existing look and behaviour. This
  retires the `@assistant-ui/tap` 0.9.12 override and the three assistant-ui
  Dependabot ignores introduced in 0.10.1 for
  [#517](https://github.com/microclaw/microclaw/issues/517)
  ([#523](https://github.com/microclaw/microclaw/pull/523)).
- Tool-call cards in the web UI show their arguments: the web stream now
  publishes `input` on `tool_start`, and the adapter accepts `call_id` /
  `preview` as the server sends them (#523).
- A Playwright browser smoke test (`web/e2e`) boots the built binary, signs
  in, types and sends in the real embedded composer, reloads and types
  again; a new `Web UI Browser Smoke` CI job runs it on every push
  ([#522](https://github.com/microclaw/microclaw/pull/522)). Pinning tap back
  to 0.9.20 makes it fail with the #517 error, so the regression class that
  shipped in v0.8.0 to v0.10.0 is now caught before release.

## Acceptance gates

- Every Rust and UI package reports `0.11.0`.
- `cargo semver-checks` accepts the bump for the public crates.
- Main CI including `Web UI Browser Smoke`, and Extended CI succeed for the
  release commit.
- `npm --prefix web run e2e` passes locally against the release-commit
  binary.
- The `v0.11.0` Release Assets workflow publishes verified binaries, the
  SDK crates publish at `0.11.0`.
