# MicroClaw v0.11.1 execution plan

Status: **Delivered**
Updated: **2026-10-27**

MicroClaw 0.11.1 is a security patch release on top of 0.11.0. It fixes a
privately reported configuration fail-open in the global tool policy:
`tool_policy.allow_tools` was an exemption list rather than an allowlist,
global tool lists did not accept wildcards, and the tool catalog sent to
the model was never filtered by the policy. Reported by nilo (nilo85).

## Scope

- Global `tool_policy.allow_tools` is a real allowlist: when non-empty,
  every unlisted tool is blocked (or warned about under `mode: warn`).
  `deny_tools` wins over `allow_tools` and `max_risk` applies to
  allow-listed tools too, so each rule only removes tools.
- Global `allow_tools` / `deny_tools` accept `*` and trailing wildcards,
  matching the grant lists.
- The tool catalog offered to the model (main loop and sub-agent loop) is
  narrowed to what the policy lets the caller run
  (`ToolRegistry::definitions_for`); `execute_with_auth` still enforces the
  policy on every call.
- `microclaw doctor` gains a `security.tool_policy` check, and
  `microclaw config check` plus startup logging warn when `tool_policy.mode`
  is on but no rule is configured.
- Docs (`docs/security/secure-runtime.md`, the example config, the web
  Governance tab labels) describe the new semantics; the changelog carries
  the migration note for operators who relied on the old exemption.

## Acceptance gates

- Every Rust and UI package reports `0.11.1`.
- `cargo semver-checks` accepts a patch bump for the public crates.
- Main CI and Extended CI succeed for the release commit.
- A GitHub Security Advisory is published for the fix with credit to the
  reporter, after the release is available.
- The `v0.11.1` Release Assets workflow publishes verified binaries, the
  SDK crates publish at `0.11.1`.
