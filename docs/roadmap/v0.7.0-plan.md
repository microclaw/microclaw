# MicroClaw v0.7.0 execution plan

Status: **Active**
Updated: **2026-09-29**

MicroClaw 0.7.0 makes provider prompt caching effective across turns. The
system prompt and the stored history stay byte-identical between turns, per-turn
context is attached at request time, and cache token usage is reported so the
effect is observable. The minor version reflects the two public fields added to
`microclaw-core` `Usage`.

## Scope

- Stable cached prefix: the live clock, query-matched memories, ranked skill
  bodies, and other per-turn context move into a transient `<turn_context>`
  block that is never persisted.
- Stable plugin tool ordering and whole-second UTC message timestamps.
- `system_prompt_time_detail` config (`none` / `date` / `full`, default `date`).
- Prompt-cache token accounting in LLM usage and agent metrics.
- nixpkgs update tooling can refresh the open init pull request.

## Acceptance gates

- Every Rust and UI package reports `0.7.0`.
- Main CI and Extended CI succeed for the release commit.
- `microclaw-core`, `microclaw-engine`, and `microclaw-sdk` publish at `0.7.0`
  and pass the public API compatibility check.
- The `v0.7.0` workflow publishes verified binaries and multi-architecture
  containers, and the complete Release Assets workflow is green.
