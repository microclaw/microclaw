## 0. Release thesis

v0.3.x built the dependability machinery: durable turn checkpoints and recovery, delivery
outbox, completion contracts, secure runtime (principals + egress + sandbox credential
hygiene), Learning Foundry, heartbeat, token budgets, governance UI, and the Reliability Proof
Pack. All of it is merged and released.

The 2026-08 intel pass shows the category caught up on the *claims*: OpenClaw, Hermes, and
ZeroClaw all shipped crash-surviving delivery within a month of ours. What none of them ship is
**evidence**. v0.4.0's job is to make MicroClaw's dependability *provable, operable, and
supported*:

> **Provable** — every release carries published, reproducible evidence (scorecard, benchmark,
> self-assessment). **Operable** — a self-hoster sees and is alerted about health without
> Grafana or YAML. **Supported** — an LTS channel answers "can I run this for a year".

No new agent capabilities in this cycle. The Q3 roadmap's scope fence stands: everything below
serves a user surviving their first 10 minutes and a bot surviving 30+ unattended days —
now with receipts.

## 2. Milestones

Working cadence: three ~3-week milestones from today (2026-08-07), tag in the window the Q3
roadmap already set (early October).

- **M1 — "Evidence out" (by 08-28):** A1 · E1 · D1 spike concluded with decision doc ·
  B4 catalog structure landed (strings can trickle in) · A2 method defined and harness running.
- **M2 — "Operable" (by 09-18):** A2 numbers published · B1 · B2 · C1 · E2.
- **M3 — "Supported" (by 10-09):** C2 · B3 · E3 · A3 · F2 · release soak per promotion
  policy → **v0.4.0 tag + LTS-1 branch (10-10)**. D2 only if the D1 decision was low-risk and
  M1/M2 ran clean; otherwise it opens v0.5.0.

Every item follows the standing per-PR checklist from
[`feature-completion-tracking-board.md`](./feature-completion-tracking-board.md); autonomous or
isolation-changing behavior ships **off by default** (C2, B2, B3 are all opt-in).

## 3. Exit criteria (release gate)

1. Release page links a reproducible reliability scorecard and a tokens-per-task benchmark
   with method (A1, A2).
2. A self-hoster can see health on one `/status` surface and receive at least one alert class
   via webhook without external tooling (B1, B2).
3. Every high-risk tool approval renders as a structured option card on web and control chat
   (C1).
4. A tampered installed skill fails closed at load with an actionable message (E1).
5. Plugin-host direction is decided and documented; RFC 0006 updated or superseded (D1).
6. `v0.4-lts` exists with a written backport policy; a v0.3.x instance upgrades with the guide
   and passes migration checks, and can roll back (F1, F2).
7. Standing guarantees hold: zero default-behavior change; CI has zero tolerated-red; OWASP
   self-assessment published (A3) unless explicitly cut with rationale.

## 4. Non-goals (re-affirmed)

No enterprise SaaS build-out, no meeting bots/wearables/voice, no MoA model mixing, no
channel-count race, no vector-DB core dependency, no self-modifying tool code. Local inference
needs no work (llama.cpp speaks the OpenAI-compatible protocol we already support).

## 5. Risks

- **Evidence backfires if sloppy.** A2's comparison methodology must be defensible
  (pinned versions, published scripts, same tasks) — a debunked benchmark is worse than none.
  Mitigation: publish raw logs alongside numbers; invite reproduction.
- **Approval UX fragmentation across channels.** Option cards render differently per platform
  (Telegram buttons vs Slack blocks vs plain text). Mitigation: one semantic model in core,
  per-channel renderers with a plain-text fallback; the fallback is the contract.
- **LTS support cost for a solo-maintainer project.** 3-month security-only window is the
  ceiling; backport criteria must be strict and documented so LTS never blocks main.
- **D2 temptation.** Shipping a half-isolated plugin host to hit the tag date is the one
  failure mode this plan forbids: D2 is stretch by design; the isolation boundary ships when
  it's right, not when it's October.
- **Cadence slip.** M1 is deliberately light (mostly wiring + writing); if M1 slips, cut
  should-items at M2 rather than moving the tag — LTS-1's date is the commitment that matters.
